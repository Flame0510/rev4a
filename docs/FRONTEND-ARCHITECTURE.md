# Rev4a Frontend Architecture

> **Last updated:** 2026-10-13

## Layering

Rev4a UI should follow a layered architecture:

1. `app/*/page.tsx` — routing only, plus the page title: `export const metadata = { title: 'Lineage' }`. The root layout adds the template, so the browser tab reads "Lineage · Rev4a"; a page without a title shows "Rev4a — Revolution for Agents". A client-only page (`app/login`) gets its title from a small `layout.tsx` next to it. The home page (`app/page.tsx`) shares the root layout's segment, where the template does not apply, so it sets `{ absolute: 'Dashboard · Rev4a' }`. A new page must set its title.
2. `app/components/*Page*.tsx` — page composition and data orchestration.
3. `app/components/ui/*` — shared design-system primitives.
4. `lib/patterns/*` — domain/data patterns.
5. `lib/*` — infrastructure helpers and pure utilities.

Feature pages should not create new ad-hoc visual languages. Prefer `ui` primitives first.

## UI primitives

All shared UI primitives live in `app/components/ui/` and are exported from `app/components/ui/index.ts`.

### Rules

1. **Prefer existing primitives over new ad-hoc markup.** Every new component starts from the shared catalog.
2. **No inline styles on interactive elements.** Buttons, inputs, selects use the `app/components/ui/*` component with component props. Only layout/wrapping containers use inline style.
3. **No Italian in code, labels, or comments.** UI strings, error messages, aria-labels — all English.
4. **Clickable/custom interactive elements must be `<button type="button">`.** Not `<span onClick>`, not `<div onClick>`. Always include `aria-label` for icon-only buttons.
4a. **A control gated on another field stays visible and disabled** — never conditionally unmounted. Rendering it only once its dependency is filled makes it appear out of nowhere, and any hint that references it is pointing at something not on screen. Show it disabled, with the reason beside it, so the shape of the form is stable from the first render.
5. **Modals inside forms** — close button has `type="button"` to prevent accidental form submission.
6. **Loading buttons** — set `loading={true}` on `Button`, do not render separate loaders next to the button. The spinner is built-in. The label must also change for the duration (`Saving…`, `Deleting…`, `Syncing…`).
6a. **One in-flight mutation, keyed.** Hold a single `busy` string identifying the running action (`delete:<id>`, `sync:<id>:<container>`), plus a `useRef` mirror as the authoritative guard — state is read from the render that produced the click, so two fast clicks would otherwise both pass. `loading` compares against the exact key; `disabled` is set for any busy value, so a control that would be refused looks refused. Never key a mutation on one dimension when the same control is rendered per row of another: a key holding only a container name puts every profile's button for that container into a spinner.
6b. **Do not hold the lock across a slow refresh.** Release it when the mutation itself completes and refresh derived state afterwards, unawaited. Show the pending state by fading the stale values only — never the buttons, since `opacity` on an ancestor cannot be undone by a child and makes live controls read as disabled.
6c. **An optimistic update moves every field the render derives from, together.** A row that decides its state by reading two fields against each other flips to a third, wrong state if the update touches only one of them — and holds it until the slow refresh lands. Update the whole set the derivation reads, or none of it.
6d. **On/off state is a `Switch`.** A persistent enabled/disabled state (start/stop, enabled, delivered) uses `Switch`, with `loading` set from the same keyed `busy` value as rule 6a and `disabled` for any busy value. A one-shot action (Delete, Retry, Sync) stays a `Button`.
7. **New UI component** — add it to `app/components/ui/`, export from `index.ts`, document it here. If it's specific to one page, keep it page-local unless another page needs it.

7a. **Agents are labelled by display name; the container name is only a secondary detail.** Wherever an agent is shown (tabs, pills, headers, table rows, select options, modal titles, confirm dialogs, toasts, empty states, error messages) the label is its display name, the container's `AGENT_NAME` env (`displayName` / `agentName` / `name` in the API payloads), falling back to the container name only when the agent has none. The container name may appear as small muted text or a `title` tooltip, never as the main label. Container names stay in URLs, request bodies and React keys. API responses gain `displayName` / `agentName` additively. The names are read by `lib/agent-names.ts` (`getAgentDisplayNames`): one batch `docker inspect` printing only `AGENT_NAME`, cached for 15 s — never a `docker exec` per agent. The Containers page lists agents by display name and passes it to the terminal page as `?name=` (a label only).
8. **`×` means remove, `✕` means dismiss.** They look alike and are not the same
    action. Removing an item from a list uses `RemoveButton`; dismissing a dialog
    is the `Modal` component's own close control. Do not build a third variant of
    either, and do not reuse one for the other.

    *Outstanding:* four dialogs predate the shared `Modal` and roll their own close
    control — the edit dialog and the `openclaw.json` dialog in
    `app/agents/PageClient.tsx` (both a `ghost` Button with `✕`), the drawer in
    `app/components/SessionDrawer.tsx` (a bare `<button>`), and
    `app/components/ModelPickerModal.tsx` (`model-picker__close`, which compounds
    the problem by using `×`, the *remove* glyph, to dismiss, and omits
    `type="button"`). The fix is to move them onto `Modal`, not to extract a
    `CloseButton`: they also reimplement Escape-to-close and overlay behaviour.
    `ModelPickerModal` has no importers at all, so deleting it is the cheaper fix
    there.

    Separately, `app/agents/PageClient.tsx` has a raw `×` delete-backup button with
    no accessible name that should be `RemoveButton`.

## GoF pattern mapping

Already used:

- **Observer + Singleton**: `EventBus` owns one SSE stream and fan-outs updates.
- **Factory**: `SessionFactory` / `EventFactory` normalize raw runtime data.
- **Adapter**: `ApiAdapter` converts raw API payloads to domain types.
- **Strategy + Composite**: `FilterStrategy` composes dashboard filtering.

Lineage page (`/lineage`) and the dashboard's session figures read the sessions of every agent container (`agent_sessions`, via `GET /api/sessions` and the SSE `sessions` frame):

- **Identity is `uid`** = `<container>|<session_key>`; two containers can hold the same key. The drawer asks `/api/session?container=&key=` from the uid.
- **The tree** (`buildSessionTree` in `lib/patterns/sessionPresentation.ts`) is container (agent display name, "stopped" marked) → `main` → sessions → sub-agents at any depth → cron runs, by `parent_uid`. A missing parent or a loop hangs the session from `main`.
- **Status** comes from OpenClaw (`running` is "working", `failed` is "error", `aborted`), never from the clock; a row of a gone container is not working. Cost is `null` when unpriced and shown as "not priced", never $0. All times are milliseconds.
- **Filters** (agent = container, period, active only, no cron) are pure functions in `sessionPresentation.ts`; `?agent=` still accepts an old display name and falls back to `all`. A period longer than the stream's 7 days is read from `/api/sessions?since=` and refreshed every 30 s.
- The Live feed names the agent of each event; the dashboard's "Active sessions" counts working sessions across containers.
- **Graph layout** (`layoutTree` in `sessionPresentation.ts`, drawn by `SessionTopology.tsx`): every leaf owns a vertical slot of `NODE_BLOCK_HEIGHT`, so labels never overlap (a very large tree fits at a small scale and may need panning), and each depth is a column as wide as its widest label plus `DEPTH_GAP`, so a parent's label never meets its child's. Labels are cut at `LABEL_MAX_CHARS` with an ellipsis (`truncateLabel`); the tooltip carries the full text. A session without a price shows "not priced" under its label, never a missing line. The view fits the tree on load and "Reset view" refits it (zoom down to 0.05); it refits on its own only when the tree structure or the filters change (`topologyFitKey`), never because a session's cost, state or model changed, and a redraw interrupts a fit in flight and runs it again.
- Tested without a browser by `scripts/test-lineage-ui.mjs` (the logic files import types only, so Node runs them).

Added UI-side discipline:

- **Factory-ish tone mapping**: `toneFromHealth()` maps domain health into UI tone.
- **Strategy-ish variants**: `Surface` variant/tone classes choose presentation without inline restyling.
- **Composition**: page-specific components compose primitives instead of duplicating card markup.

## Responsive system

Rev4a uses Bootstrap v5 breakpoint categories as project-wide tokens, declared in `app/globals.css`:

- `--bp-sm: 576px`
- `--bp-md: 768px`
- `--bp-lg: 992px`
- `--bp-xl: 1200px`
- `--bp-xxl: 1400px`

Rules:

1. Prefer breakpoint tokens over raw pixel values.
2. New responsive behavior should map to Bootstrap categories (`sm`, `md`, `lg`, ...), not ad-hoc thresholds.
3. When an exception is needed, express it relative to a token and document why.

- **Agents page**
  - below `lg` (`< 992px`) switches to stacked/mobile mode

## Workspace page

`/workspace` (`app/workspace/WorkspaceClient.tsx`, with the tree in `app/workspace/Tree.tsx` and the URL helpers in `app/workspace/url-state.ts`) browses and edits the files of one agent container, under `/root/.openclaw/workspace/` (paths are shown relative to it). There is no host ("Local") workspace: the selector lists agent containers only, and an agent that is not running is listed as "<name> (stopped)".

**Safe Markdown.** `.md` files open in preview. The preview HTML comes only from `renderMarkdownSafe` (`lib/markdown-safe.ts`): `marked` (GFM) with renderer hooks that escape raw HTML and drop images, then an allow-list pass written without a DOM. Allowed tags are the text, list, table and code tags; the only attributes that survive are `href` on `a` (`http`, `https`, `mailto` or `#`; every `a` gets `rel="noopener noreferrer" target="_blank"`) and `class="language-…"` on `code`. It is the only value ever given to `dangerouslySetInnerHTML` on this page; `scripts/test-workspace-markdown.mjs` holds the payloads.

**Media views.** PDF, images (png, jpg, gif, webp, avif, bmp, ico), SVG, audio and video open read-only with the browser's own viewer or player. The loader fetches `/api/workspace?…&raw=1` with the same abort controller and request id as a text load, turns the response into a Blob URL (`URL.createObjectURL`) and shows it (an SVG instead uses the API URL itself: a Blob URL is same-origin with the dashboard and would drop the server's CSP sandbox if the image were opened in a new tab) in `fileView` status `media` (`kind`: image, svg, pdf, audio, video). Images and SVG are an `<img>` fitted to the pane on a checkerboard background, with a Fit / 1:1 toggle (a click on the image toggles too) and the natural size in the meta bar; a PDF is an `<iframe>` (on a phone also an "Open in a new tab" link); audio is `<audio controls>` with the file name; video is `<video controls playsInline>`. There is no Save, no editor and no PREVIEW/EDIT toggle for them. The Blob URL is kept in a ref and revoked whenever another file is loaded, the workspace changes and when the page unmounts. Styles are the `.ws-media-*` classes in `app/globals.css`. A non-2xx (413 over 50 MiB, 415, 403...) shows its JSON `error` in the error panel.

**What can be edited.** Only a text file that loaded successfully has an editor and a Save button. A file is binary when its extension is on the list (images, PDF, archives, databases, fonts, audio, video, Office documents such as .docx/.xlsx/.pptx/.odt, and .bin, .exe, .so) or its content holds a NUL character: it shows a neutral "Preview not available yet" panel with its name and size. A failed read (any non-2xx; the JSON `error` text is shown, e.g. 413 too large, 403 outside the workspace, 502 not running) shows an error panel with Retry and no editor. Save is enabled only when the text is dirty; Cmd/Ctrl+S does the same, and a failed save shows the server's message under the meta bar.

**Download, conflict, logs.** The file bar of a file open as text, tail, media or binary panel has a **Download** link (hidden on an error panel, where the server would refuse it) (`<a class="ui-btn … ws-download" href="/api/workspace?…&download=1" download>`, the cookie session authorises it). The text loader keeps the file's `mtimeMs` in `fileMtimeRef`; Save sends it as `expectedMtimeMs`, and on a 409 a modal ("The file changed on the agent", or "The file was deleted on the agent" when the answer has `deleted: true`) offers "Keep editing", "Reload from the agent" (discards the edits and reloads) or "Overwrite" (saves again without `expectedMtimeMs`). A successful save stores the `mtimeMs` of the answer; when the answer has none, a note says "Saved. The conflict check is off until the file is reopened." A `.log`/`.out` file over 256 KB (a smaller one opens as an ordinary file), or a text file the API refuses with 413, opens through `tail=262144` instead: `tail` state, read-only textarea, no Save, a banner "Showing the last <size> of <size> — read-only" a "Reload" button (re-reads the last 256 KB and drops the earlier chunks) and a "Load earlier" button that prepends the 256 KB before it with `offset`/`length`, up to 2 MB held in memory, then says the rest stays on the agent. The binary panel asks `info=1` and shows the format label and size ("SQLite database · 216B"). A file in a read-only mount (`node.readOnly` or the workspace's `readOnlyPaths`) shows "Read-only, managed by Rev4a", has a read-only textarea and a disabled Save.

**Typed previews.** A text file whose name has a preview kind opens on PREVIEW (the same PREVIEW/EDIT toggle as Markdown; EDIT shows the source textarea; never in tail mode), and the Markdown preview highlights its fenced code blocks with `highlightCodeBlocks` after the HTML is set (blocks over 64 KB skipped, at most 200 KB per preview). `app/workspace/preview/` holds read-only previews that the Workspace page shows for text files. `previewKindOf(name)` returns `'code' | 'json' | 'yaml' | 'csv' | 'tsv' | 'env' | null` from the file name (extension and well-known names such as `Dockerfile`, `Makefile`, `.bashrc`, `.gitignore`; `.env`, `.env.*` and `*.env` are `env`); Markdown is not in it, the page keeps its own preview. `<FilePreview name text />` renders that view and nothing when the kind is null (the caller then shows the textarea).
- Code, YAML and JSON use highlight.js with line numbers drawn by CSS (not selectable, not copied). highlight.js and 24 languages load lazily on first use through one shared promise (`highlight-loader.ts`); if loading fails the text is shown plain. Above 512 KB (`HIGHLIGHT_MAX_CHARS`) nothing is highlighted and a note says so. The only HTML injected is the escaped text or highlight.js output for that text.
- JSON is parsed and shown pretty-printed with 2 spaces; invalid JSON shows the raw text with a banner `Invalid JSON at line X, column Y: message` (position from a small in-house scan, because engines differ). `.jsonl`/`.ndjson` shows the lines as they are and flags invalid lines.
- CSV/TSV use `lib/csv-parse.ts` (RFC 4180) and show a table of the first 1,000 data rows with a sticky header, a row-number column and "Showing N of M rows" when cut.
- `.env` files show keys and comments; every value (and any unparseable line) is masked as `••••••` until the user presses "Reveal values". A commented-out assignment (`# KEY=value`, `#KEY=value`, `; KEY=value`) is masked too. These names are `env` as well: `.npmrc`, `.netrc`, `.pgpass`, `.git-credentials`, `.gitconfig`, `.envrc`, `.pypirc`, `.my.cnf`, `.htpasswd`, `.dockercfg`, any file named `credentials` (`.aws/credentials`), `id_rsa`, `id_ed25519`, `id_ecdsa`, `id_dsa`, `*.pem` and `*.key`; the last group (private keys) is masked whole, every non-blank line, with no `KEY=value` parsing. A quoted value that spans lines (a PEM key) is masked to its closing quote, and a `.gitconfig` section header holding a quote, a URL or an `@` (`[url "https://x-access-token:TOKEN@…"]`) is masked like a value. The masking is cosmetic (it hides values from a glance or a screen share); the API still sends the whole text, and EDIT and Download show it.
- `highlightCodeBlocks(container)` highlights fenced code (`pre code.language-x`) inside the Markdown preview after its HTML is set.
- Limits, so a 2 MB file never freezes the tab: at most 20,000 lines rendered (CR, LF and CRLF all count as line breaks) with a "Showing the first 20,000 of N lines" note; pretty JSON only when nested at most 200 deep and under 4 MB (else the raw text with a note, "Too deeply nested to format" for deep nesting); CSV capped at 200 columns and 1,000 rows, the separator (`,` `;` tab `|`) sniffed from the first 20 rows and shown under the table; no highlighting for text with a line over 5,000 characters (highlight.js is quadratic on long tokens).
- The Markdown preview is rendered only up to 256 KB (`PREVIEW_MAX_CHARS`); above that the page shows the source with the note "This file is too large for the preview: showing the source.", because `marked` takes seconds on huge text.

Styles are the `.ws-pv-*` block in `app/globals.css`. Tests: `scripts/test-workspace-preview.mjs`.

**Races (rule 10).** Each file load has its own `AbortController` and a request id; only the latest may set state, so clicking A then B always ends on B. Each folder has its own request sequence (an older answer never replaces a newer one) and a folder is never listed twice at once. The re-list of the expanded folders (every 15 s while the tab is visible) never overlaps itself, stops after 3 failures (or at once on 400/502/503) with the error and a Retry, and is not started at all when Docker is down or the agent is stopped.

**Lazy tree (WS-5).** The page never asks for the whole workspace. `dirs` maps a folder (path relative to the root, `''` for the root) to `{ status, entries, error?, truncated? }`; the root is listed with `list=1`, a folder the first time it is expanded (a spinner row, or an error row with Retry), and the root plus every expanded folder whose parents are all expanded again every 15 s while the tab is visible. A folder that fails to list keeps its entries and shows its own error row with Retry; only a root failure or the agent/Docker being down pauses the updates. If the root fails, the next tick tries it again and then restores the open folders and the URL's file; a file from the URL is dropped when the user switches agent first. `Tree.tsx` renders the rows (buttons with `role="treeitem"`) and owns the keyboard navigation (up/down, Enter, right to expand, left to collapse; the focused row is kept by path, so a refresh does not move it). An entry inside a read-only mount (`readOnly` from the API, or under `readOnlyPaths`) shows a lock badge (`.ws-lock`) titled "Read-only, managed by Rev4a". The tree header holds the shared `Switch` "Show hidden files" (`hidden=1`); turning it on or off lists the open folders again. Styles are the `.ws-tree*` classes at the end of `app/globals.css`.

**URL state and changed-on-disk (WS-5).** `?agent=<container>&file=<path>&hidden=1` is read once on load (`useSearchParams`, so `page.tsx` wraps the client in `Suspense`) and written with `router.replace` (no history entries) after the first restore. `parseBrowseState` drops an unknown agent and a file outside the workspace root; the page selects the agent, lists the folders down to the file and opens it, or ignores it quietly. While a text file is open (not a tail view), `stat=1` is polled every 10 s on a visible tab; a different `mtimeMs` shows a banner (`.ws-disk-banner`): "The agent changed this file." with Reload, or, with unsaved edits, "The agent changed this file while you were editing. Saving will ask what to do." (the 409 dialog above). A deleted file says so. The editor content is never replaced without the user's click.

**Unsaved edits.** Switching file or workspace with a dirty buffer opens the shared `ConfirmModal` ("Discard unsaved changes?"); closing or reloading the tab triggers `beforeunload`. Navigating to another dashboard page through the sidebar is not intercepted.

**Page states** (one message for the whole body): list failed (Retry), Docker not running ("Check again"), no agents, agent stopped ("This agent is not running. Start it from the Agents page."). Nothing is expanded in the tree by default. The page keeps no state in `localStorage`.

## Credentials page (per-agent switches)

`/credentials` (`app/credentials/PageClient.tsx`) lists, under each stored profile, one row per agent from `GET /api/credentials/detect` and the assignments from `GET /api/credentials/assignments` (a database read, so the switches never wait for detect; when that read fails the card says so with a **Retry** and renders no switches instead of showing every credential as off). The switch state comes from detect (`credentials[]` of each agent: the container is the source of truth), not from the assignments, which are only Rev4a's intent; until detect answers the rows show a skeleton, never "off". When detect could not read the container for a provider (`present: null`) the switch shows Rev4a's setting, the row says "Could not read the agent's credentials — showing Rev4a's setting", it offers no Redeliver, and the credential's Delete stays locked. Each row has a `Switch` (checked = the agent holds this credential; danger tone while a removal is pending) plus small buttons for the actions that are not a state: **Redeliver** (switched on in Rev4a but "Not found in the agent", or a failed delivery, also "Gateway not ready — credentials not re-applied"), **Retry removal** (failed switch-off), **Remove** (clears Rev4a's own setting for a row that is "Not found in the agent"; it never touches the container: when the agent holds ANOTHER credential of the same provider the call is sent with `intentOnly: true`, because a provider-wide removal would delete that other credential). A credential found in the agent that this Rev4a did not switch on shows on with "Found in the agent"; switching it off sends `held: true`. When the agent holds another credential of the same provider the row shows an info `Pill` "holds <label>" (or "an unknown credential") next to the agent name, so the profile reads apart from the name. There is no "delivered natively" vs "delivered the old way" distinction: switching a credential on delivers it the current way, whatever an earlier release left on the agent. Each action has its own busy key (`on:`, `off:`, `forget:` + profile + container); the switch spins unless a button beside it already carries the same action. The switch has a stable accessible name ("<credential> delivered to <agent>"); `aria-checked` carries the state. A switch refreshes the assignments of every profile and applies the confirmed result to the detected state at once, then detect corroborates it. Assignments whose agent detect did not list are shown after the rows with the agent's display name (`agents[]` of the assignments response; the container name as a small label): stopped or busy (the switch shows its state but is disabled with the reason, **Retry removal** is disabled too) or deleted (**Forget**). A running row's switch and buttons are disabled while `agents[].busy` is set. The Codex note, the disabled "Protected — coming later" control and the `warning`/`redeliveryFailed` toasts are part of the page. The agent panel's `CredentialsSection` (`app/agents/CredentialsSection.tsx`) is the read-only counterpart.

## Subscriptions page

`/subscriptions` (`app/subscriptions/PageClient.tsx`, skeleton in `SubscriptionsSkeleton.tsx` and `loading.tsx`, sidebar entry between Credentials and Config) renders one `Accordion` per subscription provider (today ChatGPT (Codex)). **It is asynchronous in three independent steps:** `GET /api/subscriptions` returns the agent list at once (names, running; no exec), so the rows appear immediately; each row then loads its own status from `GET /api/subscriptions?agentId=` in parallel (a skeleton line under the name while it loads, a per-row error with Retry, which also covers a server-side error such as "Could not read this agent's subscription status: the read failed"), and the models load separately from `GET /api/subscriptions/models` (a skeleton in the Models block until it arrives). The "N of M agents connected" area shows a skeleton until every row has answered. Each row shows the agent's display name (`AGENT_NAME`), the container name as a small secondary line only when it differs, and next to the account email its plan ("Plus", "Pro"). A connected agent shows its model read-only ("Model: <primary> · fallback <first fallback>", bare names) and a link "Change in the agent panel" to `/agents?agent=<id>`, which the Agents page reads once the list has loaded to select that agent. The page has no model control: the model is chosen in the agent panel.

**Per-row actions.** Disconnect is a background job: the POST answers 202, the row polls `GET …/logout` every 1.5 s, shows the running action ("Disconnecting…" on the Disconnect button) and disables only that row's other actions; the other rows stay usable. A finished job refreshes that one row. The job is also returned by the row's status read, so a reloaded page resumes it. Rules 6a-6c apply (the running job is the per-row action key, a ref guards a double click). The status read, the job poll, the list and the models each have an `AbortController` in a ref (rule 10); the POSTs that start a disconnect or a login do not (a double click is stopped by a ref guard). **Disconnect** first opens the shared `ConfirmModal` ("Disconnect <agent>? It goes back to <own model> and signs out of ChatGPT. Connecting again needs a new code."); the job poll backs off from 1.5 s up to 15 s while reads fail and gives up after 2 minutes ("Lost track of the disconnect. Refresh the row.").

**Usage limits.** `UsageBlock.tsx` (shared wording and types in `usage.ts`) opens the accordion body with one block per connected account: email and plan, a shared `Meter` per window ("5 hours", "Weekly"; normal below 80 %, warning from 80 %, danger at 100 % with a "Limit reached" line), "N% used · resets …" in local time, "Updated N min ago" and a Refresh `Button` per account with its own loading state (one refresh key per account; the other buttons are disabled while one runs, and the periodic refresh skips while it runs). It loads from `GET /api/subscriptions/usage` after the rows (skeleton meters meanwhile, an error line with Retry, an `AbortController` ref), then refreshes by itself every 60 s while the page is visible and at once when the tab comes back (quietly: no skeleton, a failure keeps the last values; the server reads OpenClaw at most every 3 minutes) and renders nothing when no account is connected. The agent panel's `SubscriptionLine.tsx` loads the same route with `?email=` and shows the compact "ChatGPT Plus · 5h 86% left · week 98% left" line, refreshed the same way.

**Skeleton.** `SubscriptionsSkeleton.tsx` mirrors the real page with the shared `Skeleton` primitive and the `ui-accordion` classes: the page header, an open accordion with its header (title, "N of M" area, account line), the Models block with chips and N agent rows, each a name line, a status pill, the model line and the button. `loading.tsx` and the page's own initial state render the same component, so the hand-over has no jump.

**Connect dialog.** `ConnectModal` (same file) uses the shared `Modal`: it starts the login (`POST …/openai/login`), then polls `GET …/login?agentId=` every 2 s with an `AbortController` ref that cancels the previous poll, and ticks a 1 s countdown to the code's expiry. States: waiting for the agent, link + code (large, Copy button), connected (email), failed / expired / cancelled (message and Retry). Cancel and closing the dialog while the login runs call `DELETE …/login`. **MODEL section.** `ModelSection` is the one place that chooses the agent's model. It loads the catalogue and the agent's model as before, plus, apart and with `AbortController` refs, the agent's connection (`GET /api/subscriptions?agentId=`) and, only when connected, the subscription models (`GET /api/subscriptions/models`). The primary picker and each fallback picker pass two `groups` to `Select` ("Rev4a proxy", "ChatGPT subscription"; the second is absent until the models arrive or when the agent is not connected). Choosing a subscription primary while the fallback list is empty pre-fills the previous primary as the first fallback with the note "Used when the ChatGPT subscription reaches its usage limit". `app/agents/SubscriptionLine.tsx` is the read-only status line under the pickers ("Loading subscription models…", or "Subscription: not connected — connect it on Subscriptions"). `ModelSection` marks a bare `openai/<id>` reference with a `subscription:` prefix when it sends it to `PUT /api/gateway/agent`, so it is not confused with a Rev4a catalogue model of the same name (stored as `rev4a/openai/<id>`).

## Login page lock

`/login` (`app/login/page.tsx`) handles the throttle of wrong passwords: from the 6th wrong password the address is locked for 30 s, doubling up to 15 minutes, and the login route answers `429` with a `Retry-After` header. The page keeps `lockedUntil` (epoch ms, from `Retry-After`) and a one-second `clock` that ticks only while a lock is active; while locked, the sign-in button (and Enter) is disabled until `lockedUntil`, and the page shows the server's fixed message ("Try again in N seconds."), not a live countdown. A restart of Rev4a clears the lock.

## Request orchestration rule

For interactive pages that can change view/file/tab quickly:

1. Abort obsolete fetches with `AbortController`.
2. Guard against stale updates after `await` boundaries.
3. On navigation/context switch, kill in-flight requests before starting new ones.
4. Mobile layout changes must not wait on network completion.
5. After a mutation, refresh the cheap endpoint and await it; fire the expensive one without awaiting. A page that re-reads everything makes the user wait on work their change did not need.
6. A refresh helper invoked from a mutation must never reject. The mutation has already succeeded by then, so a failed re-read surfacing as the caller's error reports a completed action as failed.
7. Check `res.ok` before reading the body. An error response is still valid JSON, so `json.items ?? []` silently turns a 401 into an empty result presented as fact.

## Migration rule

For every new/changed page:

1. No new one-off card styles unless justified.
2. Use `app/components/ui/*` primitives first — `Button`, `Input`, `Select`, `Modal`, `Toast`, `Surface`, `Metric`, `StatusCard`, `Meter`, `TimeSeriesChart`, `Pill`, `Page`, `Tabs`, `ItemList`, `AgentCard`, `FilterBar`, `PropertyList`, `TemplateOption`, `LoadingSpinner`, `MemoryLimitPicker`.
3. Async data must render skeleton, not fake zero values.
4. Business logic stays in `lib`/API routes; UI consumes typed payloads.
5. If a pattern is introduced, name it and keep it in `lib/patterns` or `app/components/ui`.

## Scrolling on a phone (Agents page)

`.app-shell__content` is a bounded flex column (100svh minus the top bar and the bottom navigation). A page inside it must give its root `flex: 1; min-height: 0; overflow: hidden` and have **one** scrolling region (`flex: 1; min-height: 0; overflow-y: auto`); a root without `min-height: 0` grows with its content and the inner scroller never gets a bounded height, so nothing scrolls. Never use `100dvh` inside the shell: it ignores the top bar and the navigation. On /agents (phone) the header and filter row stay fixed; banners, the Gateway Token form and the list scroll together, in that order (the form scrolls away and the list gets the screen). The detail keeps its BACK header fixed and scrolls banners and panel together. `node scripts/ui-check-agents-mobile.mjs` checks this in a browser against a running instance (see its header for the environment variables).
